# 마음잇다 (Maum:Link)

Social-emotional learning web app for 3rd-grade slow learners. A child works through short illustrated everyday situations using the loop **상황 → 감정 → 생각 → 행동 → 피드백**, fully voiced, with no scores and no wrong answers.

Built as a static, offline-first PWA: React 19 · TypeScript · Vite · Tailwind 4 · Zustand · Zod. No backend, no accounts, no analytics.

Current release: **1.0.0** — see [release notes and known limitations](./CHANGELOG.md).

## Run

```bash
pnpm install
pnpm dev            # http://localhost:5173
```

Requires Node ≥ 20 and pnpm 10. First-visit audio needs one tap on **시작하기** (browser autoplay policy).

### Recorded Korean narration

Narration is pre-recorded. `src/services/narration/<voice>.json` maps exact text to bundled
MP3s under `public/audio/…`, one folder per voice set; `src/services/narration/voices.ts`
lists the sets and picks the shipped one (`DEFAULT_NARRATION_VOICE`, or the
`VITE_NARRATION_VOICE=<id>` build variable). Recorded phrases take priority over browser
synthesis, including composed messages when every phrase has a recording. Missing phrases
retain browser narration. Navigation and mute cancel the entire recording sequence; only the
shipped voice's MP3s go into the service worker precache. The app never calls a TTS
service at runtime.

| id | voice | folder | status |
|---|---|---|---|
| `lulu-lolipop` (default) | ElevenLabs **Lulu Lolipop - High-Pitched and Bubbly** (kid voice), ID `ocZQ262SsZb9RIxcQBOj`, Eleven v4, emotion tags per phrase recorded in `content-source/narration/lulu-lolipop-generation.json`, played at 0.85x | `public/audio/ko-lulu/` | 127/127 phrases |
| `kyung` | ElevenLabs **Kyung - Warm, Calm & Clear** (adult), ID `JQaWvPoEUkcuOTfxFYpJ`, Eleven v4 | `public/audio/ko/` | 126/127 phrases (kept for a later switch) |
| `sophie-lane` | KidVoice (kid-voices-ai.com) **Sophie Lane**, Korean child voice | `public/audio/ko-kid/` | 1/127 (KidVoice credits ran out) |
| `clova-ndain` | NAVER Cloud CLOVA Voice **다인** (`ndain`, 여자 아동), TTS Premium, speed 2 | `public/audio/ko-clova-ndain/` | generate with the script below |

CLOVA Voice sets are generated by script, once, from the developer account's keys in
`.env.local` (`NCP_CLOVA_CLIENT_ID`, `NCP_CLOVA_CLIENT_SECRET`; never committed, never shipped):

```sh
pnpm narration:generate:clova --sample "오늘은 어떤 마음을 배워볼까요?" --speakers ndain,ngaram,nhajun --speeds 0,2,4 --out ../voice-samples
pnpm narration:generate:clova --voice clova-ndain      # every phrase not yet recorded → .narration-downloads/clova-ndain
pnpm narration:import .narration-downloads/clova-ndain --voice clova-ndain
```

Other voices: add a `src/services/narration/<id>.json` with the CLOVA `voiceId` (speaker code), register it in
`voices.ts`, and run the same two commands with `--voice <id>`. CLOVA child speakers: `ndain` 다인, `ngaram` 가람 (girls), `nhajun` 하준 (boy).

To add or change phrases: run `pnpm narration:inventory` to refresh
`content-source/narration/inventory.json` (phrase ids are shared by all voice sets),
generate each missing phrase verbatim in the provider's web app, save the download as
`<clip id>.mp3` (or `.wav`), then run `pnpm narration:import <directory> --voice <id>`
(re-encodes with ffmpeg when available and updates that voice's manifest). Do not put
provider credentials in the app. Free plans are often licensed for personal, non-commercial
use; confirm commercial usage rights before distributing the recordings to the client.

## Quality gates

```bash
pnpm validate:final-content # exact Korean PDF transcription + no drafts
pnpm validate       # content rules (PRD §10) — also runs inside `pnpm build`
pnpm lint           # oxlint + prettier
pnpm typecheck
pnpm test           # vitest: reducer, validator, components, i18n, speech
pnpm test:acceptance # all browser checks + screenshots for review, no baseline comparison
pnpm test:e2e       # playwright: happy paths, 11-viewport responsive matrix, rotation, offline
                    # first time: pnpm test:e2e:install
pnpm build          # validate + tsc + vite build + service worker → dist/
```

The browser acceptance workflow runs Chromium/WebKit checks on Linux and uploads review screenshots. A green acceptance run does not establish visual approval; inspect its attachments. Standard `test:e2e` still compares checked-in visual baselines.

`pnpm test:e2e` builds first and starts its own preview server on port 4173 (it refuses to reuse a stray one).

## Content

Everything the child sees is data:

```
content/
  emotions.json          # 15 feelings: word, icon, tint
  ui.json                # UI strings
  scenarios/*.json       # one file per situation — add a file, it appears on Home
```

Source wording and omissions: [`docs/CONTENT_REVIEW.md`](./docs/CONTENT_REVIEW.md). The four shipped lessons match the reviewed PDF transcriptions; source typos are preserved and three missing explanations are explicit. Existing generated illustrations remain.

Korean is the shipped language. `en` strings are optional and only used by the dev flag `?lang=en` (D17). Strings marked `"draft": true` are placeholders awaiting client review; `pnpm draft-strings` lists them.

Asset pipelines (all idempotent, outputs committed):

```bash
pnpm images   # content-source/images/*.png → public/img (WebP 800/1600 + PNG)
pnpm app-icons # favicon.svg → PWA and Apple touch icons
pnpm icons    # scripts/gen-icons.ts → public/icons/{emotions,outcome,domain}
pnpm fonts    # Noto Sans KR subset (KS X 1001 + content glyphs) → public/fonts  (needs `uv`)
```

## Deploy

The app is a static folder. After `pnpm build`, upload `dist/` to any static host; the service worker and manifest are included.

| Host | Command |
|---|---|
| Vercel | `vercel deploy dist --prod` (framework preset: Other, output dir `dist`) |
| Netlify | `netlify deploy --dir=dist --prod` |
| GitHub Pages | push `dist/` to the `gh-pages` branch; if served from a sub-path set `base` in `vite.config.ts` |
| Any web server | serve `dist/` with `index.html` as the SPA fallback for unknown paths |

Headers to set if the host allows: `Cache-Control: no-cache` for `index.html` and `sw.js`; long-lived caching for `/assets/*` (content-hashed).
