작성: 2026-10-09. 기준: [SPEC.md](./SPEC.md), 결정: [DECISIONS.md](./DECISIONS.md). 상태는 `완료 / 진행 중 / 대기 / 보류`만 사용한다. 이전 앱에 유사 코드가 있어도 새 요구로 검증하기 전에는 완료가 아니다.

## 현재 상태와 진행 방법

현재 저장소는 React 19·TypeScript·Vite 8 기반 PWA다. 8-1 현재 총 15편으로, 기본형 10편과 단계형 대표 5편(C04·B02·C01·C05·D04)의 흐름·저장·완료를 검증했다. 아래 표와 6-1f 설명의 12편 수치는 당시 구현 이력이다. 6-1f 이후 새 메인 경로는 `시작→아바타→지도→영역 목록→행동 선택→좋은 행동 나누기→완료`로 12편 모두 연결했다. 과거의 `상황→감정→생각→행동→피드백` 4편 코드는 보존했지만 앱 라우터에서 제거했다. `Feeling.tsx`, `Step3.tsx`, `EmotionTile.tsx`, 이전 스키마/엔진/저장/검사는 추후 정리 대상이다. 새 진행값은 옛 `maumlink.progress.v1`과 분리된 `maumlink.progress.mvp-v1`에 둔다.

각 작업은 관련 코드와 명세 확인 → 작은 구현 → 관련 자동 검사 → 화면/접근성 확인 → 이 문서에 실제 명령·결과 기록 순서로 진행한다. 기준 명령은 `pnpm validate`, `pnpm typecheck`, `pnpm test`, `pnpm lint`, `pnpm build`; 화면 흐름은 관련 Playwright 검사와 실제 기기 확인을 더한다. 기존 `pnpm validate:final-content`는 옛 PDF 문구 검사이므로 새 콘텐츠에는 별도 검증기를 준비한다. `pnpm test:e2e`의 기존 스냅샷은 과거 디자인일 수 있어 재검토 후 갱신한다. 자동 검사의 성공과 아동/교육자 검토를 혼동하지 않는다.

### 6-1 세부 계획 — 제공된 생활 정원 HTML 시안으로 UI 전환

**적용 범위:** 사용자가 제공한 `마음마을 생활정원.html`은 생활 정원 목록과 A02의 질문·좋은 선택·순서 맞추기·순서 완료·활동 완료, 총 6개 화면의 동작 시안이다. 새 시각 방향은 앱 전체에 적용하되 A02를 첫 검증 화면으로 삼는다. 시안 위의 화면 선택 탭과 검은 휴대폰 테두리는 시연용이므로 앱에는 넣지 않는다. HTML에 없는 시작·아바타·지도·상황 도입·오답·힌트·예시·나머지 11편도 같은 시각 언어로 설계한다.

**이식 방식:** HTML은 6.9MB 자체 포함 번들로, 그림 4장·Jua 글꼴 조각·별도 React 실행 코드가 포함된다. 현행 React 19 앱에 HTML의 상태 코드와 고정 문구를 복사하지 않고, `DomainEpisodes`, `EpisodeIntro`, `BehaviorGame`, `ChoiceCard`, `SpeechBubble`, `Card`, `VoiceToggle`의 데이터와 동작을 유지하며 레이아웃·색·타이포그래피를 적용한다. 새 그림은 기존 devkit과 비교한 뒤 필요한 것만 분리한다. 글꼴은 사용권·묶음 크기·본문 가독성을 확인한다. 시안의 `2/12·17%`는 예시이며 실제 완료 기록을 계속 사용한다.

| 순서 | 구현 범위 | 완료 기준 | 상태 |
